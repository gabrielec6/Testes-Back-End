Testes Back End

Bem-vindo ao Back End Testing

O back end é a parte do sistema que roda no servidor: regras de negócio, banco de dados, APIs e segurança. Testá-lo garante que tudo funcione antes de chegar ao usuário.

Nesta página você vai ver os documentos de teste, como elaborar casos de teste, executar, monitorar, avaliar resultados e se comunicar com a equipe de automação.

A. Documentos de Testes

Planejar, registrar e reportar

Os documentos de teste registram o que será testado, como, o que aconteceu e qual foi o resultado final.

1. Plano de Teste

Define o escopo, a estratégia, os recursos, o cronograma e os riscos dos testes.

  • Objetivos e itens a testar (ex.: API de pedidos, banco de dados)
  • Tipos de teste: unitário, integração, desempenho, segurança
  • Ambiente, ferramentas e responsáveis
  • Critérios de entrada e saída

2. Casos de Teste

Descrevem cada verificação: dados de entrada, passos, resultado esperado e condições prévias. Veja a seção Caso de Teste.

3. Relatório de Incidentes de Testes

Registra cada falha encontrada para que seja corrigida.

4. Relatório de Resumo de Teste

Emitido ao final, resume o que foi executado e conclui se o sistema está pronto.

  • Total de casos executados, aprovados e reprovados
  • Incidentes abertos e corrigidos
  • Cobertura alcançada
  • Recomendação: liberar ou não o software

B. Elaboração do Caso de Teste

Conceito

Um caso de teste é um conjunto de condições, entradas e passos que verifica se uma funcionalidade se comporta como esperado. Cada caso deve ter um resultado esperado claro.

Boas práticas: ser objetivo, independente dos outros casos, repetível e rastreável até um requisito.

Estrutura básica

  • ID e título
  • Pré-condições
  • Passos e dados de entrada
  • Resultado esperado
  • Resultado obtido e status

C. Execução do Programa

Na execução, os casos de teste são rodados no ambiente preparado, comparando o resultado obtido com o esperado.

Passos da execução

  1. Preparar o ambiente e o banco de dados de teste
  2. Subir a aplicação (servidor e dependências)
  3. Executar os casos manualmente ou com ferramentas (Postman, JUnit, pytest)
  4. Registrar o resultado: aprovado, reprovado ou bloqueado
  5. Abrir incidentes para as falhas encontradas
  6. Repetir os testes após as correções (reteste e regressão)

Exemplo prático

Comando para rodar os testes automatizados de um projeto Python:

pytest tests/ --verbose

D. Monitoramento e Controle

Monitorar é acompanhar o andamento dos testes; controlar é tomar ações quando algo foge do plano.

O que acompanhar

  • Casos executados x planejados
  • Quantidade de incidentes abertos e fechados
  • Tempo gasto e prazos
  • Cobertura de código e de requisitos
  • Desempenho do servidor (tempo de resposta, uso de CPU e memória)

Ações de controle

  • Redefinir prioridades quando houver atraso
  • Reforçar testes em módulos com muitos defeitos
  • Reavaliar riscos e atualizar o plano de teste

E. Avaliação de Resultados

Ao final, os resultados são analisados para decidir se o software atende aos critérios de qualidade.

Como avaliar

  • Comparar os resultados com os critérios de saída do plano de teste
  • Calcular a taxa de aprovação: aprovados / executados x 100
  • Analisar a densidade e a gravidade dos defeitos
  • Verificar a cobertura dos requisitos
  • Identificar riscos que ainda restam

Exemplo: de 100 casos, 94 aprovados = 94% de aprovação. Se a meta era 95%, é preciso corrigir e retestar antes de liberar.

A avaliação alimenta o Relatório de Resumo de Teste e as lições aprendidas para os próximos projetos.

F. Comunicação com a Equipe de Automação de Testes

A equipe de automação transforma casos de teste manuais em scripts. Uma boa comunicação evita retrabalho e testes desatualizados.

Boas práticas

  • Compartilhar casos de teste claros e priorizar os que mais se repetem (regressão)
  • Informar mudanças de requisitos e de APIs o quanto antes
  • Alinhar ambientes, dados de teste e ferramentas
  • Reportar falhas dos scripts com evidências (logs e prints)
  • Fazer reuniões curtas e usar canais como chat e quadros de tarefas

Exemplo de mensagem

"Pessoal, o endpoint /pedidos passou a exigir o campo cliente_id. Por favor atualizem os scripts CT-05 e CT-06 até sexta."
